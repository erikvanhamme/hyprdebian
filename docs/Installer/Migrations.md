## Introduction
Migrations are one-off changes that `upgrade.sh` makes to systems that were installed or upgraded before the change. See [Upgrade](Upgrade.md#migrations) for how they run, and [migrations/README.md](../../migrations/README.md) for how to write one.

Each migration first checks whether its change is needed, and is recorded as done without changing anything when it is not.

## Migrations so far
| Migration | What it does |
| --- | --- |
| `0001-resolv-conf-uplink` | When `/etc/resolv.conf` does not point to `/run/systemd/resolve/resolv.conf` yet: installs `systemd-resolved` when it is missing, and points `/etc/resolv.conf` to `/run/systemd/resolve/resolv.conf`, like `svc_systemd` does on a new installation. Installing `systemd-resolved` points it to the stub resolver, which `00-direct-uplink.conf` turns off. |
| `0002-network-file-names` | Older versions named the network files after the interface (`50-<interface>.network`, `60-<wifi interface>.network`). Moves them to `50-ethx.network` and `60-wlanx.network`, so the upgrade compares them with the templates, or removes the old file when the new one is already there. |
| `0003-machine-id-rotation` | Older versions deleted `/etc/machine-id` on shutdown with `clear-machine-id.service`, so systemd saw every boot as a first boot and applied the presets. Disables and removes that service, which `rotate-machine-id.service` replaced, and masks `systemd-firstboot`, `systemd-preset-all` and `systemd-machine-id-commit`, like `svc_systemd` does on a new installation. |
| `0004-libvirt-masks` | When libvirt is installed, masks `libvirtd-tcp.socket`, `libvirtd-tls.socket` and the `10-secret.conf` drop-in of `libvirtd.service`, like `svc_qemu_kvm` and `pkg_qemu_kvm` do on a new installation. Without them, libvirtd fails on a missing systemd credential key. Restarts libvirtd when it is enabled. Unlike the installer, it does this whenever libvirt is installed, also when it is only there for virt-manager. |
| `0005-apt-sources` | Older versions defined the apt sources in the one-line format, in `/etc/apt/sources.list` and `sources.list.d/hyprdebian.local.list`. Renders `debian.sources` and, when the local repo is enabled, `hyprdebian.local.sources` from the templates when they are missing, like `b_apt_init`. Moves `sources.list` to `sources.list.bak`, which apt does not read, removes `hyprdebian.local.list` once `hyprdebian.local.sources` is there, and runs `apt update`. When the local repo is not enabled in the answers, `hyprdebian.local.list` is kept, so the repo is not lost. |
| `0006-efi-sync-hook` | Older versions deployed the apt hook that runs `hd-sync-efi` on redundant installations to `/etc/apt/conf.d/99sync-efi`, which apt does not read, and let it call `/usr/local/sbin/hd-sync-efi`, which does not exist, so the secondary EFI partition was never synchronized. Removes the old hook, and `/etc/apt/conf.d` when it is empty. The upgrade adds the fixed hook in `/etc/apt/apt.conf.d` and installs `rsync`, which `hd-sync-efi` needs. |
| `0007-efi-automount` | Older versions mounted the EFI partitions from `/etc/fstab`. Renders `boot-efi.mount`, and `boot-efi2.mount` on redundant drives, from the UUID in the fstab entry or of the mounted partition, adds the `.automount` units and enables them, like `b_mount_unit` does on a new installation. Then removes the entries for these mount points from `/etc/fstab`, keeping a copy in `/etc/fstab.bak`. The partitions stay mounted, and the automount units take over on the next boot. Units that are already there are left alone. |
| `0008-swap-encryption` | Older versions used the swap partition unencrypted, also on an encrypted root filesystem. When the root is encrypted and `/etc/fstab` has a swap partition by UUID: installs `systemd-cryptsetup`, turns the swap off, adds the swap to `/etc/crypttab` with a random key on each boot, like `b_crypttab`, and points the swap entry in `/etc/fstab` to `/dev/mapper/swap`, keeping a copy in `/etc/fstab.swap.bak`. Then starts the encrypted swap, and rebuilds the initramfs, which would otherwise wait for the old swap partition to resume from on every boot. When the memory cannot hold what is in the swap, turning it off fails, and nothing is changed. The old partition is not wiped: what the old swap held stays on it until the encrypted swap overwrites it. |
| `0009-rpcbind-masks` | Older versions did not mask `rpcbind`, which `nfs-common` pulls in, and which listens on the network. Masks `rpcbind.socket` and `rpcbind.service`, like `svc_systemd` does on a new installation. They are not stopped, because that could disturb an NFSv3 mount, so `rpcbind` stops on the next boot. |
| `0010-cups-avahi-sane` | Older versions installed `avahi-daemon` and `sane-utils` with cups, as recommended packages. Both listen on the network, and printing does not need them. On systems with cups, removes the ones that are installed, like `o_cups` keeps them out on a new installation. When removing them would also remove other packages, like a desktop environment that uses avahi, they are kept with a warning, and the migration is recorded as done. |
| `0011-griffo-apt-key` | Older versions used the `debian.griffo.io` repo. Its source was dropped first, but its key `/etc/apt/trusted.gpg.d/debian.griffo.io.gpg` was deployed up to v0.80, so apt still trusts it for every repo. Removes the key, and `/etc/apt/sources.list.d/debian.griffo.io.list` when it is still there, followed by `apt update`. |
| `0012-zfs-atime-off` | Older versions created `bpool` and `rpool` with `relatime`, so reading a file could still write its access time. Sets `atime=off` on the pools that do not have it yet, like `f_boot_pool` and `f_root_pool` do on a new installation. The datasets inherit it, unless they set atime themselves. |
| `0013-ufw-logging-off` | Older versions left the logging of ufw on, which writes a line for every blocked packet. On systems with the firewall and ufw installed, turns the logging off when `/etc/ufw/ufw.conf` does not have `LOGLEVEL=off` yet, like `pkg_enable_firewall` does on a new installation. |
| `0014-os-prober` | Older versions installed `os-prober` with grub, as a recommended package. It mounts the partitions of other disks on every `update-grub`, to look for other operating systems. Removes it, like `b_grub2` keeps it out on a new installation. When removing it would also remove other packages, it is kept with a warning, and the migration is recorded as done. |
| `0015-pipewire-user-links` | Older versions enabled `pipewire` and `wireplumber` for the user with links in `~/.config/systemd/user/default.target.wants` that point into `/mnt/usr/lib/systemd/user`, so they are broken. The pipewire packages enable their user services themselves. Removes these links when they point into `/mnt`, and the directory when it is empty. |
| `0016-root-bashrc` | Older versions left the `.bashrc` of Debian for root, which does not load `~/.bash_aliases`, the file the upgrade adds for root. Updates `/root/.bashrc` and `/root/.bash_logout` from `/etc/skel`, like `u_root_skel` does on a new installation. A missing file is added, and for a file that differs, the user chooses to keep, replace or merge it, like for the other changed files. |
| `0017-iscsi-unit-typo` | Older versions queued `iscsi-login.service` for the backup tools from the misspelled `deploy/etc/systemd/sytem`. The installation created `/etc/systemd/sytem`, and then failed to copy the unit without stopping. Removes that directory when it is empty, and an `iscsi-login.service` in it. The upgrade adds the unit in `/etc/systemd/system`, like `o_backuptools` does on a new installation. |
| `0018-package-cleanup` | Older versions installed `qemu-guest-agent` on all machine types, `yazi` also on console systems, and `cmake`, `meson`, `ninja-build` and `pkg-config` as build tools. For each group, the installed packages that the new version does not install on the system are offered for removal. The user is asked once, with no as the default. When removing them would also remove other packages, they are kept without asking. |
| `0019-mdadm-removal` | Older versions of the upgrade installed `mdadm` on every system, as a package the upgrade itself needed. Without an array, the initramfs looks for one on every boot, and the boot waits for it. Purges `mdadm` and rebuilds the initramfs, unless the system has redundant drives with swap, which use the swap array like `b_mdadm` installs it. When the system has an active array, or removing `mdadm` would also remove other packages, it is kept with a message, and the migration is recorded as done. |
| `0020-no-resume` | HyprDebian does not support hibernation, but without a configured resume device, the initramfs picks a swap partition to resume from, and waits for it on every boot ("Gave up waiting for suspend/resume device"). Deploys `/etc/initramfs-tools/conf.d/resume` with `RESUME=none`, like `b_buildtools` on a new installation, and rebuilds the initramfs. |
| `0021-hyprdebian-motd` | Older versions showed the login messages of Debian. Empties `/etc/motd`, removes `/etc/update-motd.d/10-uname`, and diverts `/etc/issue` to `/etc/issue.debian` with `dpkg-divert`, like `b_motd` does on a new installation, then writes the hyprdebian `/etc/issue` with `write_issue`. The upgrade adds `/etc/update-motd.d/00-hyprdebian`, which shows the hyprdebian banner after a login. |
| `0022-signed-repo` | Older versions trusted the local hyprdebian repo without checking signatures (`Trusted: yes`). When the local repo is enabled, downloads its signing key from the repo to `/usr/share/keyrings/hyprdebian-archive-keyring.pgp` and renders `hyprdebian.local.sources` again, which checks the signatures with that key, like `b_apt_init` does on a new installation. Runs `apt update`. When that fails, for example because the repo is not signed yet, the old `hyprdebian.local.sources` is put back and the upgrade stops, so the migration runs again on the next upgrade. |
